## Set Up
1. Pull this repo to you local machine or onto a DeepDish server.
2. Ensure that the provided data is organized as shown above in the directory tree diagram. 
3. We first set up the conda environment. Use `cd` commands to navigate into this repository. Then, run `conda create --prefix ./.venv python=3.12`.
4. Activate this virtual environment: `conda activate ./.venv`.
5. Install the necessary requirements, `pip install -r requirements.txt`.
6. If you would like to run the attached notebook, to generate plots, create a jupyter notebook kernel for this environment: `ipython kernel install --user --name=<any name for kernel>`.

## Instructions for running Federated Averaging algorithms.
1. The following instructions should be run from the base of this directory. 
2. You can modify the hyperparameters for training by editing the parameters in the `main()` method in the respective files `src/q1/fed_avg/main.py `, `src/q1/parallel_clients/run_parallel.py`, and `src/q2/run_dp.py`. Or, if you prefer, for both the parallel runs and the differential policy run, `run_dp`, you can specify the hyperparameters via the command line, as demonstrated in the argparse.  
3. To run the models, from base directory, execute the following commands: 
``` 
python3 src/q1/fed_avg/main.py # Runs the standard, sequential, FedAvg algorithm
python3 src/q1/parallel_clients/run_parallel.py # Runs FedAvg in parallel via Ray
python3 src/q2/run_dp.py # Runs Differential Privacy on sequential FedAvg algorithm.
```
4. [WARNING] The use of a terminal multiplexer, Tmux, is highly encouraged especially when running on a remote server. To create a new Tmux, `tmux new -s fed_avg`, `tmux new -s fed_avg_parallel`, and `tmux new -s diff_privacy` to run all algorithms simultaneously. Then, run `tmux attach -t fed_avg`, `tmux attach -t fed_avg_parallel`, `tmux attach -t diff_privacy` to enter these terminals. Inside each window, you may now run the corresponding scripts using the commands from step 3.
5. The outputs for each run, as a result, will be printed to the command line interface for the respective algorithm/multiplexer combination.
6. For the `fed_avg` sequential run, note that if you want to sweep over different values of epochs and communication clients to use, uncomment the commented code in `src/q1/fed_avg/main.py` found in the execution block. This will output a plot showing training performance over different combinations of epochs and communical clients. 

## Instructions for running Validation Tests
1. Ensure that `run_validations.sh` has appropriate permissions: `chmod +x scripts/run_validations.sh`.
2. Then, execute ` ./scripts/run_validations.sh`. This will run all validation tests for the three scenarios including a non standard plot.
3. To only run a specific validation test, you may pass in additional parameters to the terminal to only run these tests for a given scenario. That is, `.scripts/run_validations.sh fedavg parallel dp plot` will run all the validation tests as well, and you can mix and match the passed parameters to run the tests you desire. The results of the edge cases and validations for each scenario will then be stored under `results/validation`. The associated plots that are generated will be stored under `validation_figures`.
